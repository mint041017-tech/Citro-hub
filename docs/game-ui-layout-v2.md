# Citro 游戏页布局规范 v2

> 适用范围：所有 `GameScaffold` 游戏页，**后续新增游戏必须按本规范套用**。嵌入型 WebView 页（极限刹车、咕噜果冻旧壳）按同一视觉方向逐步收敛。
> 实现：`flutter/lib/games/game_ui.dart` 的 `GameScaffold`；自定义按钮/胶囊统一复用 `GameActionButton` / `GameHover`，不另造页面骨架。

## 断点与骨架

- **竖屏**：`width <= height`。
- **横屏**：`width > height`。
- 页面背景仍为 Citro 纸面 + 方格。

### 竖屏

```
┌──────────────────────────────────────────┐
│ [返回] 游戏名                [HUD 数据看板] │ 64 高（+ 系统安全区）
├──────────────────────────────────────────┤
│           [above 难度/模式胶囊]            │ 紧贴棋盘上方
│                 游戏棋盘                   │
│            [actions 操作按钮行]            │ 紧贴棋盘下方
│                                          │
├──────────────────────────────────────────┤
│ 正在玩（固定在底部）                       │
└──────────────────────────────────────────┘
```

- 顶栏 64 高（比旧 56 略高），显示返回、当前游戏名、HUD 数据；HUD 居右；**不显示 logo、头像、账号入口**。
- 游戏名紧贴返回按钮右侧，单行省略。
- HUD 数据在顶栏最右侧；数据项多时整体缩放/横向排布，不换行成多行顶栏。
- `above`（难度/模式切换胶囊）在**棋盘上方**，紧贴棋盘。
- `actions`（开始、撤销、重开、选关、暂停、排行榜等所有可交互按钮）在**棋盘下方**，紧贴棋盘。
- 数据看板只展示只读数据（分数/用时/步数/星级/剩余次数等），**不放任何可交互按钮或难度切换**。
- 棋盘占据中间剩余空间；内容超高时允许棋盘区内部滚动作为兜底，但正常尺寸不能出现滚动。
- “正在玩”固定底部，不跟随棋盘滚动。

### 横屏

```
┌──────────────┬──────────────────┬─────────────────────┐
│ [返回]        │ [above 难度胶囊]   │ 游戏名              │
│              │      游戏棋盘      │ [HUD 数据看板]       │
│ 排行榜        │ [actions 按钮行]   │                     │
│              │   紧贴棋盘上下      │─────────────────────│
│              │                  │ 正在玩               │
└──────────────┴──────────────────┴─────────────────────┘
```

- 左侧 sidebar（`210–248`）保留排行榜；返回按钮与「排行榜」标题放在左栏顶部同一行，榜单内部不再重复标题。
- 右侧 sidebar 宽 `clamp(270, 340)`；只放游戏名 + 「数据看板」只读数据 + 正在玩，不放任何按钮或难度切换。
- 中间列固定为「难度/模式胶囊 → 棋盘 → 操作按钮行」的纵向顺序，上下都紧贴棋盘；没有 h1、logo、账号、底部 live 条。
- 横屏已有常驻排行榜栏，**按钮行不再显示排行榜按钮**；竖屏仍保留排行榜按钮。

## 数据与语义

- `pills` / `hud`：**只放只读数据**（分数、用时、步数、星级、剩余次数等），不得混入按钮或难度切换。
- `above`：难度/模式等整行切换控件，渲染在棋盘上方。
- `actions`：所有操作按钮（开始、撤销、重开、选关、暂停、排行榜等），渲染在棋盘下方。
- `above`/`actions` 紧贴棋盘上下；不要固定到屏幕底部。
- 桌面端交互反馈：所有可点击控件（按钮、难度/模式胶囊、可选卡片）都要有鼠标悬停动效（轻微抬升/放大 + 手型光标）。`GameActionButton` 自带；自定义控件统一套 `GameHover`。
- `board`：棋盘本身。棋盘内只允许游戏内容浮层（标题、入场、选关、结算、Toast）和玩法输入区（方向键、数字盘、道具条）；不允许再放页级 HUD、难度切换或页级操作按钮。
- 游戏名、HUD、难度切换、操作按钮、正在玩均由 `GameScaffold` 提供，游戏页不另造顶部/侧栏/底部 chrome。

## 验收尺寸

- 竖屏：390×844、466×678、678×1024、1024×1366。
- 横屏：844×390、951×669、1280×800、1366×1024、1440×1000。
- 检查项：顶栏无 logo/头像；游戏名/HUD 不重叠；难度/模式胶囊在棋盘上方、操作按钮在棋盘下方且都紧贴棋盘；数据看板内无按钮；棋盘尽量大且不被裁切；live 固定；无横向溢出；棋盘区无意外滚动。
