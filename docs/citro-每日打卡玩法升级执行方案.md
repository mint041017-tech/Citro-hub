# 1. 背景与目标

## 1.1 现有基础

Citro 的每日打卡已经具备完整的内容与视觉底子：

- 48 支运签，8 个等级 × 6 支；
- 10 种签类：事业、学业、心事、人际、身体、行动、钱袋、收工、灵感、小事；
- 本地签池按日期轮换，AI 结合日期、农历、节气、卡面等写「今日解」；
- 每日卡面与卡面收藏；
- 下签 / 下下签可分享好事后转运；
- 「今日一小步」可勾选，按天保存在本机；
- 首页打卡卡、连续天数与跨端同步；
- Flutter 页面、分享图片、本地通知等基础能力均已存在。

## 1.2 当前断点

打卡目前更接近一次性的内容消费：

1. 用户抽完签、看完解签，当天行为就结束了。
2. 「今日一小步」只在当天生效，没有形成可回看的历史。
3. 连续天数能证明用户来过，却不能呈现这些日子留下了什么。
4. 抽签结果与计划、专注、听隅、记账、笔记等现有模块没有连接。

## 1.3 一期目标

把打卡从「每天抽一支签」升级成轻量的每日记录系统：

- 每天增加一个低负担的收尾动作；
- 让今日行动与 Citro 现有能力产生连接；
- 每累计七次打卡形成一份可以回看的个人长卷；
- 游客本地即可完整使用，登录用户支持跨端同步；
- AI 不可用时，所有核心流程仍能正常运行；
- 不制造新的断签焦虑，不扩张积分经济。

## 1.4 一期成功标准

用户即使不分享、不联网、不使用 AI，也能完成：

> 抽签 → 行动 → 回签 → 七次成卷

登录后，这些记录还能安全地跨端保留。

# 2. 一期范围与边界

## 2.1 一期要做

1. **晚间回签**：给当天写一个落点和一句可选记录。
2. **七日成卷**：累计七次打卡自动形成一卷，可查看、保存、分享。
3. **签类行动联动**：十类签分别映射到任务、专注、听隅、记账、笔记等入口，并提供手动完成兜底。

## 2.2 一期明确不做

- 不改变连续天数计算规则；
- 不增加补签卡、积分、经验值、排行榜；
- 不把回签内容默认发到社区；
- 不强制用户每日打开两次；
- 不新增 AI 请求；
- 不接第三方统计平台；
- 不恢复小程序中的打卡页面；
- 不同时开发好事银行、明日来信、全服同签日；
- 不为每一种签单独搭建独立的小游戏或活动页。

## 2.3 产品原则

- **记录优先**：打卡的价值是留下痕迹，而不是完成 KPI。
- **不惩罚漏签**：七日成卷按累计次数计算，不要求连续。
- **手动永远可用**：自动验证失败时，用户仍能自行完成。
- **私密默认**：回签、任务、账本内容不进入公开纪念图。
- **轻量入口**：不新增红点催办，不用焦虑文案。
- **向后兼容**：旧客户端继续使用原有打卡、转运、抽卡逻辑。

# 3. 整体用户流程

## 3.1 首次打开今日打卡

沿用当前流程：

1. 用户点击首页「打卡」。
2. 调用 `showCheckinOverlay()` → `showFortuneOverlay()`。
3. 读取或抽取今日运签。
4. 展示卡背、翻面、签文、AI 解签与今日卡面。
5. 首次创建当天的 `CheckinDayEntry`。
6. 保存当天内容快照：
   - 日期；
   - 签等级；
   - 签 ID、签题、签类；
   - 当前卡面 ID；
   - 今日行动文案与行动类型；
   - 是否为转运后的版本。
7. 根据签类生成「今日行动」入口。

必须保存内容快照，而不是只保存签等级。否则后续签池、文案、卡面目录发生变化时，历史长卷会变形。

## 3.2 完成今日行动

签面下方在「今日一小步」位置增加轻量入口：

> 今日一小步  
> 把拖了三天的那句话说出口  
> 「去安排」　「我自己完成了」

规则：

- 点击主按钮跳转对应功能；
- 能自动验证的行动，完成后自动盖章；
- 不能自动验证的行动，保留手动勾选；
- 完成行动只改变当天卡面纪念状态，不额外送抽卡机会；
- 用户不完成行动，也不影响打卡和七日成卷。

## 3.3 晚间回签

当天已经打卡后，无论几点再次打开，都能看到「给今天收个尾」。

18:00 后，首页打卡卡把副标题切换为回签提示，但不弹窗、不强制跳转。

回签分两部分：

1. **今天的落点，三选一**
   - 如签所说
   - 走了自己的路
   - 不想归类

2. **留一句话，可选**
   - 最长 120 字；
   - 默认仅自己可见；
   - 不输入文字也可以保存落点。

保存后：

- 今日卡面出现「已回签」印章；
- 七日长卷对应格子由线稿变成彩色；
- 首页状态变为「今天收好了」；
- Toast 显示「今天收好了」。

回签之后仍可修改，修改不增加任何计数。

## 3.4 七日成卷

每累计七个不同的打卡日期，自动完成一卷：

- 11 月 1 日打卡：第 1 格；
- 11 月 2 日漏掉：不处罚；
- 11 月 3 日打卡：第 2 格；
- 后续累计集满七格：完成第 1 卷；
- 下一次打卡：自动开启第 2 卷。

完成后展示：

> 第 1 卷已经集齐  
> 这七次来到 Citro 的日子，替你收成了一卷。

操作按钮：

- 「展开这一卷」
- 「保存纪念图」
- 「先看看下一卷」

不强制分享，不自动打开发布面板。

# 4. 晚间回签

## 4.1 页面结构

新增独立底部弹层 `reflection_sheet.dart`，不要把输入框直接塞进现有的长签面。

页面从上到下：

1. 标题：「给今天收个尾」
2. 今日签摘要：签题、签类、日期
3. 今日行动完成状态
4. 三个落点选项
5. 回签输入框
6. 隐私说明：「只保存在你的打卡记录里，不会自动公开」
7. 主按钮：「收好今天」
8. 次按钮：「今天先不写」

输入框占位文案：

> 今天有什么小事，值得留一句？

## 4.2 首页状态机

| 当前状态 | 首页主状态 | 副标题 |
| --- | --- | --- |
| 今日未打卡 | 待打卡 | 翻开今天的签 |
| 已打卡，未完成行动 | 已打卡 | 今日一小步还等着你 |
| 已完成行动，未回签，18:00 前 | 已打卡 | 今天已经留下了脚印 |
| 已打卡，未回签，18:00 后 | 待回签 | 给今天收个尾 |
| 已回签 | 已收好 | 今天收好了 · 连续 N 天 |
| 数据同步中 | 保持原状态 | 不显示阻塞加载 |
| 同步失败 | 保持本地结果 | 已存本机，联网后再同步 |

「待回签」只作为视觉状态，不使用红点、倒计时或催促文案。

## 4.3 日期与补写规则

- 登录用户以服务端返回的 UTC+8 日期为准；
- 游客使用设备本地日期；
- 打卡只能创建在当天；
- 回签可以在之后通过历史长卷补写；
- 补写仍归属于原打卡日期，不改变连续天数；
- 历史回签可以编辑；
- 不提供“删除某天打卡”，因为会破坏七日成卷的稳定性；
- 跨天后，首页不再提醒昨天未回签。

## 4.4 隐私规则

- 回签默认永久私密；
- 不进入社区动态；
- 不发送给 CiCi；
- 不作为 AI 解签上下文；
- 不进入公开个人主页；
- 纪念图默认不包含回签正文；
- 只有用户主动勾选后，才允许在纪念图中加入一条摘录。

# 5. 七日成卷

## 5.1 成卷算法

以用户所有有效打卡日期排序，每七条组成一卷：

- 同一天重复打开只算一次；
- 转运不增加次数；
- 完成行动不增加次数；
- 回签不增加次数；
- 漏打卡不清空已有格子；
- 不设过期时间；
- 完成第七格后，下一次打卡进入下一卷。

卷号根据记录顺序计算：

> 卷号 = 当前记录序号 ÷ 7 向上取整

一期不提供单条打卡删除，因此历史卷号保持稳定。

## 5.2 长卷页面

新增 `checkin_scroll_page.dart`，页面分三个区域。

### 顶部：当前卷概览

- 「第 N 卷」；
- 起始日期至当前日期；
- 已收进 X / 7 天；
- 七个格子进度；
- 不使用“断签”“失败”等词。

### 中部：七日内容

每格包含：

- 日期与星期；
- 当日卡面缩略图；
- 签题、签类；
- 今日行动是否完成；
- 是否已回签；
- 一句公开安全的短签文摘要。

状态表现：

| 状态 | 视觉 |
| --- | --- |
| 未到来 | 浅色虚线格 |
| 已打卡，未完成行动 | 普通卡面 |
| 已完成行动 | 卡面角落增加小印章 |
| 已回签 | 卡面彩色化，并显示回签标记 |
| 卡面资源加载失败 | 用日期与签题生成纸质占位卡 |

### 底部：历史卷与操作

- 查看上一卷；
- 保存当前纪念图；
- 分享纪念图；
- 继续下一卷。

历史卷允许补写回签，但不重新发放完成奖励。

## 5.3 纪念图内容

采用 **1080 × 1440、3:4 PNG**。

布局：

1. Citro 标识与「第 N 卷」；
2. 日期范围；
3. 七张签面缩略卡；
4. 每张卡对应的日期、签题、行动状态；
5. 底部固定收尾：
   > 日子不必连续，来过就有痕迹。

默认不出现：

- 回签正文；
- 用户昵称；
- 账号 ID；
- 地理位置；
- 私密笔记；
- 具体账本金额；
- 具体任务标题。

用户主动勾选后，才可以加入一条回签摘录。

## 5.4 成卷奖励

一期只给纪念性奖励：

- 卷尾印章；
- 一个完成日期标记；
- 一张可保存纪念图。

不送抽卡机会，避免多设备、改时间、重复同步刷奖励，也避免冲击现有卡面经济。

# 6. 签类行动联动

## 6.1 通用行动模型

每个行动包含：

| 字段 | 说明 |
| --- | --- |
| `actionType` | 行动类型 |
| `actionText` | 用户实际看到的文案 |
| `actionStatus` | `pending` / `done` |
| `linkedId` | 关联任务、账本记录、笔记等 |
| `completedAt` | 完成时间 |
| `verifyMode` | `auto` / `manual` |
| `completedActionText` | 完成时的文案快照 |

通用行动类型：

- `task`：计划任务；
- `focus`：专注；
- `listen`：听隅；
- `ledger`：记账；
- `note`：记录；
- `community`：社区互动；
- `manual`：手动确认。

## 6.2 十类签映射

| 签类 | 推荐行动 | 自动验证 | 手动兜底 |
| --- | --- | --- | --- |
| 事业签 | 选择一条计划任务作为今日推进项 | 关联任务完成 | 「我已经推进了」 |
| 行动签 | 先做五分钟，可进入专注 | 专注达到 5 分钟 | 「我开始了」 |
| 学业签 | 专注学习十分钟 | 专注达到 10 分钟 | 「我学完了一小段」 |
| 收工签 | 听隅放松十分钟 | 有效播放达到 10 分钟 | 「我让自己休息了」 |
| 身体签 | 起身、喝水或听一会儿声音 | 走听隅验证 | 「我照顾了一下自己」 |
| 心事签 | 写一句心情或完成回签 | 保存心情或回签 | 「我已经记下了」 |
| 钱袋签 | 记一笔或核对一笔旧账 | 新增一条账本记录 | 「我核对过了」 |
| 灵感签 | 记下此刻的一个念头 | 保存笔记或回签 | 「我记下来了」 |
| 人际签 | 问候一个人，或认真回应一条动态 | 发布一条评论 | 「我问候过了」 |
| 小事签 | 完成签面原本的一小步 | 不强制自动验证 | 手动勾选 |

## 6.3 按钮与交互

主按钮文案按行动变化：

- 「去计划」
- 「开始五分钟」
- 「去听隅」
- 「记一笔」
- 「写下来」
- 「去回应」

次按钮统一为：

- 「我自己完成了」

原则：

- 不自动创建公开动态；
- 不自动发评论；
- 不自动记账；
- 不读取外部聊天、健康或通讯录数据；
- 不将用户带入一个无法退回的流程。

## 6.4 自动验证原则

自动验证只统计用户点击行动入口之后产生的新行为。

- 打卡前已经完成五条任务，不自动完成事业签；
- 点击「去计划」后，用户选择或新建任务并关联；
- 只有关联任务完成，才自动盖章；
- 记账必须点击「记一笔」后新增记录；
- 听隅只累计前台有效播放，不要求后台权限；
- 自动验证失败时，始终保留手动完成。

## 6.5 转运边界

这是开发时最容易遗漏的部分。

### 尚未完成行动

- 今日签改变后，行动入口跟随新签更新；
- 清除旧的关联关系，但不删除任务、笔记等用户数据；
- 尚未开始的计时直接取消；
- 已保存的回签内容保留。

### 已完成行动

- 不撤销「已做到」状态；
- 保存原行动文案到 `completedActionText`；
- 新签可以展示新建议，但不重复发放印章；
- 长卷显示当前签，同时保留原行动完成记录。

### 已回签后转运

- 回签正文和落点保留；
- 不清空用户已经写下的内容；
- 长卷使用最新签信息，并保存回签修改时间。

# 7. 数据结构

## 7.1 每日记录模型

新增 `CheckinDayEntry`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `date` | String | `YYYY-MM-DD` |
| `signId` | String | 签池中的稳定 ID |
| `signTitle` | String | 当时展示的签题快照 |
| `levelIndex` | int | 0–7 |
| `kind` | String | 十类签之一 |
| `cardId` | String? | 当日卡面 |
| `transferUsed` | bool | 是否为转运后版本 |
| `actionText` | String | 当前行动文案 |
| `actionType` | String | 通用行动类型 |
| `actionStatus` | String | `pending/done` |
| `linkedId` | String? | 关联对象 |
| `completedActionText` | String? | 完成时快照 |
| `completedAt` | int? | 完成时间 |
| `reflectionMood` | String? | `same/different/unrated` |
| `reflectionText` | String | 0–120 字 |
| `reflectionUpdatedAt` | int? | 回签更新时间 |
| `createdAt` | int | 首次打卡时间 |
| `updatedAt` | int | 最后更新时间 |
| `rev` | int | 服务端版本号 |

`pendingSync` 只作为本地字段，不上传服务端。

AI 的完整解签不存入每日记录，避免历史数据膨胀；只保存展示所需的短文本快照。

## 7.3 本地存储

新增前缀：

```text
citro_checkin_days_v1_<账号>
citro_checkin_days_v1_guest
citro_checkin_outbox_v1_<账号>
citro_checkin_ui_v1_<账号>
```

用途：

1. 每日记录本地缓存；
2. 待同步操作队列；

# 8. 服务端接口

旧接口保持原字段，新增字段和接口均为增量，确保旧版 App 不受影响。

## 8.1 保留并扩展

### `GET /api/checkin/stats`

保留：

- `date`
- `last`
- `checkedInToday`
- `streak`

新增：

- `today`：当天完整记录，没有则为空；
- `rev`：当天记录版本。

### `POST /api/checkin`

继续负责连续天数和首次打卡。

新客户端额外提交当天快照：

- `signId`
- `signTitle`
- `levelIndex`
- `kind`
- `cardId`
- `actionText`
- `actionType`
- `transferUsed`

同一天重复请求返回原记录，不重复创建。

## 8.2 新增接口

| 方法与地址 | 用途 |
| --- | --- |
| `PUT /api/checkin/action` | 更新行动文案、关联对象和完成状态 |
| `PUT /api/checkin/reflection` | 保存或修改回签 |
| `GET /api/checkin/history?before=日期&limit=35` | 分页读取历史记录 |
| `GET /api/checkin/bootstrap?days=35` | 启动时一次获取统计、今日记录和近期长卷数据 |

## 8.3 请求字段

### 行动更新

- `date`
- `done`
- `actionText`
- `actionType`
- `linkedId`
- `rev`

使用“设置为完成 / 未完成”，不要使用含义不明确的 toggle。

### 回签更新

- `date`
- `mood`
- `text`
- `rev`

## 8.4 更新规则

- `rev` 不一致时返回 `409` 和最新记录；
- 同一天重复完成保持幂等；
- 回签重复保存不增加计数；
- 历史日期只能更新已有打卡记录；
- 不能通过接口给没有打卡的过去日期补卡；
- 同一天重复打卡不新增历史记录。

## 8.5 服务端校验

- 所有新接口必须登录；
- 请求体限制在 16 KB；
- 日期严格匹配 `YYYY-MM-DD`；
- 签 ID、卡面 ID、关联 ID 限制长度和字符；
- `levelIndex` 限制为 0–7；
- `kind` 只接受十种合法值；
- `actionType` 只接受预定义类型；
- `actionText` 最长 60 字；
- `linkedId` 最长 64 字；
- `reflectionText` 最长 120 字；
- `mood` 只接受 `same/different/unrated`；
- 写入与查询分别限流；
- 历史分页每次最多 62 条。

# 10. 离线与跨端同步

## 10.1 本地优先

所有操作先写本机，再尝试同步：

- 回签保存后立即显示成功；
- 网络失败不回滚文字；
- 记录进入 `pendingSync`；
- 下次启动、恢复登录或再次打开长卷时重试；
- 网络错误不使用阻断弹窗；
- 同步失败时界面不出现“记录丢失”等误导提示。

## 10.2 队列规则

- 以「日期 + 字段」合并同类操作；
- 多次修改回签，只同步最后一次；
- 行动与回签分别排队，避免互相覆盖；
- 创建当天记录必须先于行动、回签同步；
- 同一天重复同步不产生新格子；
- 注销账号时清空对应队列，防止数据写入新账号。

## 10.3 冲突处理

- 普通拉取：服务端记录优先更新云端字段，本地未同步草稿不被覆盖；
- 行动完成冲突：优先保留已完成状态；
- 回签文本冲突：保留本机草稿，并提示「另一台设备也修改过这条回签」；
- 用户再次主动保存时，基于最新 `rev` 重试；
- 不做复杂的多设备实时协同，一期保证最终一致即可。

## 10.4 账号隔离

- 登录后使用账号专属本地键；
- 切换账号时重新加载新账号数据；
- 游客记录与账号记录不自动合并；
- 首次登录且本地有游客记录时，提供一次显式「带入这台设备的打卡记录」选择，不对已有账号自动混入；
- 账号注销清除云端的 `u:昵称|*` 数据以及本机对应缓存。

# 11. AI 与内容策略

一期不需要新增 AI 请求。

- 今日签仍走现有 `FortuneAi.loadOrGenerate()`；
- 长卷标题先使用本地模板，不做 AI 周总结；
- 回签保存不做内容评分、情绪分析或“准不准”判断；
- 行动类型只由签类决定，不让模型自由生成页面跳转指令；
- AI 尚未返回时使用本地 `SignCard.step`；
- AI 返回后可以更新尚未操作的行动文案；
- 一旦用户关联对象、开始行动或完成行动，文案立即冻结；
- 历史记录保存当时实际展示的短文案快照。

后续如果增加 AI 周总结，必须：

- 由用户主动点击生成；
- 提供纯本地模板版本；
- 不把私密回签正文自动上传；
- 明确说明使用了哪些内容。

# 12. 纪念图与分享

项目已有 `RepaintBoundary`、PNG 编码与 `share_plus` 的使用基础，可以复用玩法抽签的分享方式。

## 12.1 渲染流程

1. 用独立 Widget 渲染固定比例纪念图；
2. `RepaintBoundary.toImage()` 输出 PNG；
3. 七张卡面按显示尺寸解码；
4. 卡面使用缩略缓存，避免同时加载七张原图；
5. 资源加载失败时使用纸质占位卡；
6. 输出前保证字体、暗色模式和日期排版稳定。

## 12.2 平台适配

- Android / iOS：调用系统分享；
- Web：优先复制图片或下载 PNG；
- Windows：不支持系统分享时，保存 PNG 到用户可见目录；
- 所有平台失败时，只提示「纪念图保存失败，可以稍后再试」，不影响长卷数据；
- 分享统计只记录“成功打开分享或保存流程”，不宣称用户已发到外部平台。

## 12.3 性能要求

- 纪念图只在用户主动点击时渲染；
- 不每秒重建七张完整卡面；
- 图片解码使用 `cacheWidth`；
- 渲染峰值不应导致打卡页面重新加载或明显卡顿；
- 长按保存不阻塞主线程过久，必要时显示短暂处理中状态。

# 13. 统计与效果评估

项目现有分析工作台是演示数据，一期不接第三方统计。服务端只记录匿名聚合计数，不记录回签正文。

## 13.1 指标

- 每日打卡人数；
- 今日行动完成人数；
- 晚间回签保存人数；
- 当前卷查看人数；
- 成卷人数；

- 离线待同步失败量；

1. 打卡用户里，多少人愿意完成行动；
2. 打卡用户里，多少人愿意回签；

## 13.3 原则

- 不记录回签原文；

- 不生成用户画像；
- 指标只用于判断入口与文案是否有效；
- 上线后的行为目标不作为验收门槛，先记录一到两周基线。

- 未打卡时不能凭空创建历史回签；

- 社区、公开主页和 CiCi 不会自动获得回签；
- 账号注销后云端记录被清除。

## 14.2 七日成卷验收

- 同一天打开十次只算一格；
- 转运不增加格子；
- 不连续打卡也能集齐；
- 第七次打卡只完成一卷；
- 第八次打卡进入下一卷；
- 已完成卷不会因后续打卡改变结构；

## 14.3 行动联动验收

- 十种签类都有可用行动；
- 打卡前完成的旧任务不会误触自动完成；

3. 验证旧版 App 打卡、转运、抽卡不受影响；

## 16.2 客户端功能开关

至少保留三个独立开关：

- `reflectionEnabled`
- `scrollEnabled`
- `linkedActionEnabled`

出现严重问题时，可以只关闭对应入口，不回滚整个打卡页面。

## 16.3 回滚原则

- 服务端新接口保留，不影响旧客户端；
- 客户端关闭新入口后，仍回到现有每日一签；
- 已产生的历史数据不删除；
- 不因 UI 回滚重置连续天数；
- 纪念图生成失败不影响打卡和回签。

## 16.4 数据迁移

- 旧版 `citro_fortune_step_<日期>` 读取一次并迁移到当天记录；
- 迁移失败不能阻断打卡页面；
- 迁移只在本机进行，不向其他账号写入；
- 登录用户首次同步时合并当天记录，不重算连续天数；
- 旧版本历史不做大规模伪造回填，避免生成不真实的签面。

---

# 17. 后续版本路线

## V1.1：好事银行 + 明日来信

在一期数据稳定后开发：

- 回签中标记「这是一件好事」；
- 好事独立收藏和随机翻回；
- 给明天或七天后的自己留一句话；
- 用户主动开启后，才提供晚间本地通知；
- 月末生成「这个月留下的好事」短卷。

## V1.2：天气与节气限定

- 雨天、晴天、深夜、节气形成卡面变化；
- 条件透明，不做隐藏概率；
- 只改变视觉与文案，不影响吉凶和行动奖励；
- 节气限定卡面不参与转运；
- 与现有天气、农历模块复用数据。

## V2.0：全服同签日

- 所有人共享同一支基础签；
- AI 解签和个人行动仍然各自不同；
- 匿名同题讨论默认关闭，由用户主动参与；
- 需要补充审核、举报和隐私规则后再上线；
- 不比较连续天数，不设排行榜。

# 18. 最终完成标准

一期完成必须同时满足：

- 抽签、行动、回签、成卷四个步骤均有可点击的完整路径；
- 游客不登录、不联网也能完成一次“今日记录”；
- 登录用户换设备后能看到相同打卡记录；
- 转运不会破坏已保存的回签或已完成行动；
- 七日成卷不要求连续打卡；
- 纪念图默认不包含任何私密正文；
- 所有新增行动都不影响连续天数、转运次数、卡面抽卡经济；
- 旧版 App 的打卡、转运、抽卡仍可正常使用；
- 现有签池测试、转运测试、首页布局测试全部通过；
- 新增数据可以在账号注销后彻底清除。

最终验收的一句话：

> 用户即使不分享、不联网、不使用 AI，也能完成“抽签—行动—回签—七次成卷”的完整流程；登录后，这些记录还能安全地跨端保留。
