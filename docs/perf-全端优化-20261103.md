# Citro 全端性能优化记录（2026-11-03）

## 一、审计结论

项目此前已经过多轮针对性优化，本轮先用静态扫描 + 现有 `PerfProbe` 复核，确认以下基础仍然有效，不再重复改动：

- `RootShell` 首帧只挂载当前 Tab，其余页首次访问才创建；隐藏页统一走
  `Offstage + TickerMode + RepaintBoundary`，后台不再跑动画。
- 列表默认使用 `ListView.builder` / `SliverList`（游戏页、社区页、食谱页）。
- 图片基本都带 `cacheWidth`（本轮扫描仅剩 3 处缺失）。
- 毛玻璃按平台分流：仅 iOS/iPadOS 使用 `BackdropFilter`，Android 用 tonal 面，
  Web/Windows 不做整块模糊。
- 纸张背景 `CustomPaint` 已标记 `isComplex + willChange:false`，可被引擎缓存。
- Web 已做 CanvasKit 本地托管、未使用渲染器清理、gzip 预压缩与游戏分片懒加载。

## 二、本轮改动

### Web（首屏关键路径）

`flutter/web/index.html`

1. HTML 解析阶段就为 CanvasKit 的 `canvaskit.js` / `canvaskit.wasm` 加入
   preload，与 `flutter_bootstrap.js` 并行下载，而不是等 bootstrap 解析完再
   串行发起。
2. CanvasKit 变体选择与 `flutter.js` 完全一致：只有 Blink + `ImageDecoder` +
   `v8BreakIterator` + `Segmenter` 才预取 `canvaskit/chromium/`，其余预取完整版，
   避免预取错版本反而多下一次 7 MB。
3. `obs.chimu-claw.xyz` 增加 `dns-prefetch` / `preconnect`（社区图、听隅音频源），
   首张远端图片少一次建连。
4. `tingyu-audio-engine.js` 改为 `defer`：让浏览器先发起启动脚本下载，
   41 KB 音频引擎不阻塞首屏。

`flutter/lib/perf_probe_web.dart`

5. 原来是空实现，现在补齐启动耗时与 `FrameTiming` 采样（p50/p90/max、
   build/raster、jank 数），输出到浏览器控制台，便于 Web 端对比优化前后。

### Android

`android/app/src/main/kotlin/com/chimu/crew/MainActivity.kt`

6. 新增 `onLowMemory()`：系统整体内存不足时同样通过 `com.chimu.crew/memory`
   通道清理 Flutter 图片缓存，降低进程被直接回收的概率（`onTrimMemory` 已有）。

### 通用（Android / iOS / Windows / Web 同一套 Dart 代码）

7. `overlays/ingredient_library.dart`：食材库从一次性构建全部分类的
   `ListView(children:)` 改为 `ListView.builder`，只构建可视分类；
   低端机打开食材库时不再一次性创建数百个 chip。
8. `games/gidiom.dart`、`games/gfeihua.dart`：成语/诗句链改为 `ListView.builder`。
   这两个游戏每秒计时都会 `setState`，此前会把整条链全部重建。
9. 补齐 3 处缺失的解码尺寸：
   - `tingyu/rain-nook.webp` → `cacheWidth: 1200`
   - `images/appreciation.png` → `cacheWidth: 720`
   - `images/logo.webp`（硬币）→ `cacheWidth: 240`
10. `services/image_store_io.dart`：图片磁盘缓存启动后做一次 LRU 清理
    （保留最近使用的，超过 256 MB 或 60 天未访问的删除），避免缓存目录随
    浏览历史无限膨胀拖慢目录遍历与随机读。
11. `widgets/paper.dart`：`_PaperPainter.shouldRepaint` 补全 `highlight` /
    `wallpaper` 比较，主题/壁纸切换时不会漏重绘。

## 四、复测方法

```bash
# Web：debug 运行并开启探针，控制台过滤 CITRO_PERF
flutter run -d chrome --dart-define=CITRO_PERF_PROBE=true

# Android / Windows：探针日志写入应用文档目录 citro_perf.log
flutter run --profile --dart-define=CITRO_PERF_PROBE=true
```

Web 首屏可在 Chrome DevTools → Network 确认：
`canvaskit(.chromium).wasm` 与 `main.dart.js` 已并行下载，`tingyu-audio-engine.js`
不再阻塞 `flutter_bootstrap.js` 的发起。

## 五、后续可选项（需要真机验证或产品确认）

1. **听隅页顶层重建**：`TingyuPage.build` 用一个 `AnimatedBuilder` 包住整个
   `Scaffold + NookHome`；Web 端控制器每 300 ms 轮询一次音频快照，快照变化就
   `notifyListeners`。可将外壳重建收窄为只在 `theme` / `ready` 变化时触发，
   播放进度交给页面内已有的局部 `ListenableBuilder`。收益明确，但需要逐一确认
   `NookHome` 内没有依赖外层重建的读取点，建议在真机上配合探针做。
2. **食材分组内 Wrap**：当前一个分类内仍会构建该分类全部 chip；分类过多时可在
   组内再做二级虚拟化。
3. **Android 资源裁剪**：`isShrinkResources = true` 可减小包体，但需要确认插件
   资源没有被动态 `getIdentifier` 使用，当前环境无法出 release 包验证，暂未开启。
4. **Web brotli_static**：若线上 Nginx 已装 `brotli` 模块，可在 `build_web.sh`
   里额外生成 `.br`（CanvasKit wasm 可从 gzip 2.9 MB 进一步降到约 2.2 MB）。
