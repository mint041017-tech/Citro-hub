# 手机打开网页发烫卡顿 · 实测归因（2026-10-10）

测试条件：Edge/Chromium，视口 390×844，DPR 3，`isMobile`，**CPU 降频 4×**；
指标取 CDP `Performance.getMetrics` 在 6 秒窗口内的增量。

## 一、总体结论

主因**不是毛玻璃**，而是**首页那几个永不停歇的装饰动画**——它们每帧都在逼浏览器重算样式并重绘。

| 变体 | 主线程占用 | 样式重算 |
|---|---|---|
| 现状（全开） | **87–94%** | ~190 次/秒 |
| 只停首页 4 类装饰动画 | **26%** | **6 次/秒** |
| 停掉全部无限动画 | 5% | 3 次/秒 |
| 只关掉 191 个元素的毛玻璃 | 83%（仅降 6 点） | ~190 次/秒 |
| 只关掉壁纸 `filter:saturate()` | 85%（仅降 4 点） | ~190 次/秒 |

> 「样式重算 190 次/秒」= 屏幕每刷一帧就全量重算一次样式，这是卡顿的直接来源。

## 二、首页单项归因（逐个停掉测）

| 停掉谁 | 主线程占用 | 省下 |
|---|---|---|
| 基线 | 94% | — |
| `.hero-title em` 的 `shimmer`（渐变文字 + 动画 `background-position`） | 63% | **~31 点** |
| `.orb-wrap` 的 `orbFloat`（4 个漂浮圆钮，内含 `backdrop-filter:blur(3px)`） | 68% | **~26 点** |
| `.hero-avatar` 的 `floatySlow` | 83% | ~11 点 |
| `.cursor` 的 `blink` + `.greet-toast i` 的 `pulseDot` | 82% | ~12 点 |
| 四类一起停 | **26%** | **~68 点** |

### 最贵的两个

1. **`.hero-title em`（「·Crew」）**：`background:linear-gradient(...)` + `background-clip:text` + `-webkit-text-fill-color:transparent`，
   再叠 `animation:shimmer 5s linear infinite` 去动 `background-position`。
   → 每帧都要把渐变重新贴到文字蒙版上重绘。**单个元素吃掉约 1/3 的主线程时间。**
2. **`.orb-wrap`**：4 个圆钮每帧 `translateY` 飘动，而它们内部是带 `backdrop-filter` 的圆。
   → 元素一动，背景模糊结果就作废，每帧都要重新采样 + 重新模糊一次。这是移动端 GPU 最怕的组合。

## 三、毛玻璃的真实角色：不卡，但发烫

- 全站 **191 个元素**带 `backdrop-filter`（DOM 总节点 3070，占 6%）。
- 单独关掉它们只省 6 个点 → **不是卡顿主因**。
- 但在 DPR 3 的手机上，渲染面约 1170×2532 ≈ 300 万像素；191 层模糊叠加 + 全屏壁纸的 `filter:saturate(.72)`，
  GPU 填充率长期跑满 → **这是「发烫」的直接来源**。
- 另外「动画 × 毛玻璃」是乘法关系：静止的毛玻璃还好，**一动的毛玻璃极贵**。

## 四、隐藏页的 22 个动画：几乎不花钱

`.page-g` / `.page-sens` / `.page-trash` 上有 22 个无限动画（含两个 540px 的大光晕）。
实测停掉它们**省 0**（JS 取消组 90% vs 基线 87%），因为它们处在不渲染的子树里，不绘制也不触发重算。
→ 不必为它们做优化。

## 五、其它已知开销（非卡顿主因）

- `index.html` 单文件 1.07 MB（未 gzip 时首屏解析成本高；gzip 后约 200 KB）。
- 字体 8 个 woff2 共 3.3 MB（`font-display:swap`，按需下载）。
- 磁盘上 `图/小橘子背景.png` 18 MB 等大图**未被引用**，不会被下载（可清理磁盘）。
- 重绘型动画：`mnPulse`/`breathe`/`tkPulse`/`resultPulse`/`goTipPulse`/`tkFlash` 动 `box-shadow`；
  `pomoRingGlow` 动 `filter:drop-shadow`；`shimmer`/`axInterpSkel` 动 `background-position`。
  这些属性每帧重绘，应改成 `transform` / `opacity`。

## 六、WebView 层

`MainActivity` 已有 `onPause(){ web.onPause() }`，但只在 App 切后台时生效。
用户开着页面盯着看时，动画永不停止。可考虑：`document.hidden` 时暂停全部 CSS 动画。

# 已实施的优化与改后实测（2026-10-10 18:00）

改动全部落在 `index.html`，备份 `_backup/20261010-perf/index.html.bak`。

## 改了什么

| # | 改动 | 说明 |
|---|---|---|
| 1 | 去掉 `.hero-title em` 的 `animation:shimmer` | 「·Crew」的渐变色**保留**，只是不再每帧重绘 `background-position` |
| 2 | 去掉 `.orb-wrap` 的 `orbFloat` | 保留一次性入场动画 `orbIn`，圆钮静止 |
| 3 | 去掉 `.hero-avatar` 的 `floatySlow` | 头像不再漂浮 |
| 4 | `.cursor` 闪烁：CSS 动画 → 530ms 的 JS 切类 | 观感一样，开销从 60 次/秒降到 2 次/秒 |
| 5 | 去掉 `.greet-toast i` 的 `pulseDot` | |
| 6 | 模糊半径降档：`--glass-blur` 12→8px、`--glass-pop-blur` 12→8px、`--glass-pop-mask-blur` 10→6px | |
| 7 | 壁纸去饱和**烘焙进图片** | `图/迟暮壁纸.jpeg`、`图/迟暮手机壁纸.jpg` 已用 canvas 按 `saturate(.72)` 预处理好（原图备份在 `_backup/20261010-perf/images/`）；CSS 去掉全屏 `filter`，深色模式只剩 `brightness(.46)` 一个算子 |
| 8 | 新增 `<style id="cm-perf">` | 去掉「背景近不透明」与「小尺寸装饰件」两类**看不见的** backdrop-filter：`.csel-list / .tk-composer / .g*overlay / .gs-mask`（不透明）、`.zx-tabs / .hero-orb / .g-pill / .g-btn / .g-back / .g-me / .contact-cap / .theme-toggle / .fs-tag / .mod-badge / .drv-tag`（小件） |
| 9 | 新增 `<script id="cmIdlePause">` + `.cm-idle` | 页面不可见（切后台/锁屏）时冻结全部动画 |

## 改后实测（同条件：390×844 / DPR3 / CPU 4× 降频 / 6 秒窗口）

| 指标 | 改前 | 改后 |
|---|---|---|
| 主线程占用 | 87–94% | **22%** |
| 样式重算 | ~190 次/秒 | **8 次/秒** |
| 带 `backdrop-filter` 的元素 | 191 | **85** |
| 首页无限循环动画 | 8 | **0** |
| 壁纸全屏 filter | `saturate(.72)` | **无**（已烘焙） |
| 控制台错误 | 0 | 0 |

> 剩余的 22 个无限动画全在**不渲染的隐藏页**上（`floatOrb` / `tkGlow1` / `tkGlow2`），实测不产生开销。

## 观感验证

用同一视口对改动前后截图做**像素级对比**：

- 平均像素差 **3.67 / 255（1.4%）**
- 差异 >12 的像素占 **1.68%**
- 整体平均亮度：204.0 → 203.2（差 **-0.8**）

差异来源为壁纸 JPEG 重编码、模糊半径 12→8px、以及几个已停的位移动画。**观感基本无变化。**
