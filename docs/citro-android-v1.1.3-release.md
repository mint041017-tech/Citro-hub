## 1.1 v1.1.3 启动热修（versionCode 1104）

首版 v1.1.3（1103）在部分设备上启动即闪退/卡住。根因是
`shared_preferences_android 2.5.1` 在 release(R8) 下把 Pigeon 生成代码引用的
Kotlin 协程类（`kotlin.Result`、`kotlin.coroutines.*` 等）裁掉，启动读取本地配置时抛
`NoSuchMethodError`；因为初始化在 `runApp` 之前，窗口根本拉不起来。

修复：

1. 通过 `dependency_overrides` 固定 `shared_preferences_android: 2.5.2`（官方已带
   consumer ProGuard keep 规则），新 APK 的 DEX 中已确认保留 `kotlin/Result` 等类；
2. 所有插件/存储初始化移到首帧之后，并加 10 秒超时 + 可重试的「启动失败」页，
   初始化异常不会再导致黑屏；
3. 恢复标准 native 库打包（不压缩、16KB 对齐），避免解压/加载类兼容问题；
4. manifest 关闭 Impeller，统一使用 Skia 渲染；
5. 通知初始化改为惰性，启动阶段不再申请权限。

## 3. 构建

工程路径含中文，AOT snapshotter 对原始路径编码敏感，必须从 ASCII 盘符构建。
先用 `subst` 把**当前工程**映射到盘符，并确认映射指向的是本仓库（不要沿用旧的 X: 映射）：

```powershell
subst Q: /d 2>$null
subst Q: "C:\网站web\Citro"
type Q:\flutter\pubspec.yaml | findstr /B "version:"
cd Q:\flutter
# AI 密钥本地保存在 ..\密钥\glm.key（已被 .gitignore 忽略）
$env:GLM_API_KEY = (Get-Content ..\密钥\glm.key -Raw).Trim()
flutter build apk --release --dart-define=GLM_API_KEY=$env:GLM_API_KEY
```

构建后会得到 `build\app\outputs\flutter-apk\app-release.apk`。务必用 `aapt dump badging`
复核 versionCode / versionName，再复制为 `APK/Citro-v1.1.3-release.apk`；不要把旧盘符下
的缓存产物当成新包。

native 库使用标准打包（不压缩，16KB 对齐），兼容性优先；通用 APK 约 65.3 MB。manifest 中显式关闭 Impeller，统一走 Skia（widget 截图核对也是 Skia）。
