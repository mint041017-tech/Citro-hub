# Web 首屏瘦身与桌面化改造（2026-11-23）

本轮针对「Web 端包大、首屏慢」做了五件事：横屏改用 Windows 桌面壳、字体瘦身、
wasm 链路复核、Web 端死代码清理、非首屏页面懒加载。全部改动集中在 `flutter/lib`、
`flutter/web`、`flutter/pubspec.yaml`、`flutter/tool/build_web.sh` 与 `docs/`，
未触碰后端与原生工程。

## 一、Web 横屏沿用 Windows 版 UI

判定条件（`RootShell.build`）：

```dart
final webLandscape = kIsWeb &&
    size.width > size.height &&
    CitroForm.tabletNav(size);   // width ≥ 900 且 shortSide ≥ 600
```

满足时走和 Windows / iPad 横屏完全同一条 `tablet` 分支：左侧 208pt 侧栏 +
`splitHome`（首页左栏背景、右栏卡片）。竖屏宽窗口（≥1025 但高大于宽）仍保留
原来的 `WebHomePage`，手机横屏（width < 900）仍是移动壳。

| 位置 | 改动 |
| --- | --- |
| `pages/root_shell.dart` | 新增 `webLandscape`；tablet 分支对 Web 开放；`splitHome` 加上 Web 横屏；侧栏 `showLibrary: !kIsWeb` |
| `widgets/tablet_shell.dart` | `CitroTabletSidebar` 增加 `showLibrary`，Web 端隐藏「资源库」（产物里 mods 已删，避免点进空页 + 路由错配） |
| `pages/home_page.dart` | `WebHomePage` 只在 `!tabletNav` 时接管，横屏直接落到 Windows 同款分栏首页 |
| `pages/games_page.dart` | 网页返回胶囊只在 `!tabletNav` 的宽屏网页出现 |
| `pages/community_page.dart` | 同上，浮动返回胶囊不再叠加在侧栏布局上 |
| `pages/plan_page.dart` | 待办 + 记账并排的 Windows 排版改为 `platform.isWindows \|\| (kIsWeb && sideNav)` |
| `pages/me_page.dart` | Web 桌面壳下「我的」也走浮窗（与 Windows / iPad 一致） |

验证：`test/windows_layout_test.dart`、`test/home_layout_smoke_test.dart` 全通过
（含 `windows home fits 1200x800`）。

## 二、字体瘦身与加载加速

- **删掉 500 档**：`pubspec.yaml` 的 `RoundedCN` 只保留 400 / 700。全库只有 8 处
  显式 `FontWeight.w500`，引擎会就近选 400；换来的是 **−2.29 MB 原始 / −1.24 MB gzip**，
  首屏少一次 2.3 MB TTF 解析。
- **首屏 preload**：`flutter/web/index.html` 给 400 / 700 加
  `<link rel="preload" as="font" type="font/ttf" crossorigin>`。字体不再等
  `main.dart.js` 解析完、`FontManifest.json` 回来后才发现，而是和主包并行开跑。
- `NookUI`（0.4 MB）仍留在 FontManifest：听隅/番茄钟在 `NookFull` 加载前要用它
  fallback；`nook.ttf`（2.88 MB）本来就是运行时 `FontLoader` 加载，不进首屏。

构建后 `assets/FontManifest.json` 已只剩两档，`assets/fonts` 从 10.6 MB 降到 7.09 MB
（含 .gz）。仓库里 `rounded-500-app.ttf` 源文件保留但不再打包，需要时可加回。

## 三、wasm 编译链路

线上实测（`https://chimu-claw.xyz/canvaskit/canvaskit.wasm`）：

- `Content-Type: application/wasm` ✓ —— `WebAssembly.instantiateStreaming` 可用，
  没有退化成「先下完再编译」的慢路径；
- `Content-Encoding: gzip`，2916585 B（2.78 MB）✓；
- `Alt-Svc` 带 h3，HTTP/3 已生效 ✓；
- `main.dart.js` 与 canvaskit 的 preload 已在 `index.html` 里并行发起 ✓。

结论：能省的只剩传输层。`build_web.sh` 增加可选 brotli：

```bash
WEB_BROTLI=1 bash tool/build_web.sh
```

需要线上 nginx 装了 `ngx_brotli` 并打开 `brotli_static`（`docs/nginx-citro-web.conf`
里已留两行注释）。开启后 `main.dart.js` 1.59 → 1.21 MB、wasm 2.78 → 约 2.2 MB。
**默认关闭**——线上当前没有 brotli 模块，产出的 `.br` 只是多占包体。

## 四、Web 端无用代码

扫描 304 个 Dart 文件 + 175 个资源文件：

- 没有真正的孤儿 Dart 文件。22 个「零引用」都是条件导入的成对实现
  （`*_web.dart` / `*_io.dart` / `*_stub.dart`），由 `if (dart.library.html)` 选择，属正常结构。
- 删掉 `pubspec.yaml` 里的 `splash_image.jpg` / `splash_landscape.jpg`：Dart 侧零引用，
  只在旧网页启动页用过，**−0.78 MB**。
- `assets/images/mods`（0.26 MB）仍由 `build_web.sh` 在 Web 产物里删除，原生端保留。
- `assets/card` 111 张、`tingyu/audio` 等“疑未引用”都是 `cards_index.json` /
  动态拼路径加载，不能删。

## 五、懒加载

新增 `widgets/lazy_page.dart`：`CitroLazyPage` 先 `await loadLibrary()` 分片，
期间显示同色进度条，失败可重试。

改为 deferred 的页面（`routes.dart`，前缀统一带 `Lib` 避开路由常量）：

`cook` / `calendar` / `todo` / `todo/focus` / `ledger` / `mbti` / `play` / `sens` /
`search` / `checkin/scroll` / `tingyu`

首页卡片里直接 `const XxxPage()` 的入口也同步换成延迟壳（否则页面仍会进主包）：
`home_page`（食谱、日历）、`todo_home_card`、`ledger_home_card`、`mbti/home_card`。

保持静态导入（仍进主包，属正常）：
`tingyu_page` 被 `tingyu_play_chip` 引用 4 个色常量、`checkin_scroll_page` 被
`fortune_sheet` 引用 `showCheckinVolumeDone`，两个库无法整体 defer；首页/计划/游戏/社区
/资源库五个 Tab 与 `me` / `res` 也保持静态，切 Tab 零等待。

构建结果：

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| `main.dart.js` | 6.04 MB | **5.54 MB** |
| `main.dart.js.gz` | 1.74 MB | **1.59 MB** |
| deferred 分片 | 约 0.9 MB / 少量 | 1.51 MB / 60 个 |

## 六、总体结果

- Web 产物：**66.9 MB → 62.7 MB**
- 首帧前实际下载（gzip）：**约 8.2 MB → 约 5.6 MB（−31%）**
  构成：main 1.59 + canvaskit.wasm 2.78 + 字体 2.47
- 平台包（zip）预计 46.9 MB → 约 43 MB；若再执行「剔除 *.gz 副本」的打包改造可到 34 MB 以内

## 七、需要人工复核

1. 浏览器 1200×700 / 1440×900 打开，与 Windows 客户端截图逐项对比：侧栏宽、分栏首页、
   计划页并排卡片、社区双列、资源库入口是否已消失。
2. 抽两三个页面确认 500 档字重视觉差异（标题/副标题）。
3. 首次打开食谱、日历、待办、记账、MBTI、听隅、检查签到页，确认延迟壳的 loading
   与页面接续没有闪跳（deferred 首次会多一次分片下载）。
4. DevTools → Network 过滤 `rounded-`，确认 400 / 700 各只下载一次：preload 若与引擎的
   fetch 凭据模式不匹配，浏览器会打 `preload ... is not used` 并重复下一次。若出现该警告，
   把 `index.html` 里那两行 `preload` 删掉即可（其余优化不受影响）。
