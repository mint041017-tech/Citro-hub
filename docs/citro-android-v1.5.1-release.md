## 食谱日记

1. **食材库回归**：14 分类 / 215 项，支持搜索、多选、已选回显；接入新建食谱的「食材」「调料」分组、找菜「做什么菜」和冰箱新增食材三处入口。
2. **封面位置与自由裁切**：第一步封面移到菜名上方；裁切支持单指任意拖动、双指缩放（最多 4 倍）与重置，导出 1200px 方图。
3. **恢复原版图片压缩**：封面长边 1200 / 质量 0.82，步骤图长边 1600 / 质量 0.82，统一 JPEG；超过 350KB 时质量按 12 递减至 40，仍超限则边长乘 0.75（长边下限 640）重来。实测封面 1200×1200 / 232KB，步骤图 1000×1600 / 125KB。
4. **单位表**：个、克、斤、盎司、磅、毫升、茶匙、汤匙、瓣、片、颗、根、张、块、罐、一小把、少许、少量、适量、不用单位。一小把 / 少许 / 少量 / 适量 / 不用单位不显示数量输入。
5. **删除按钮统一红色**：食材行、步骤行、步骤图移除、购物清单、食谱详情删除以及删除确认按钮。
6. **关闭与下拉**：新建食谱左上角、吃什么右上角关闭按钮放大到 42dp；吃什么和新建食谱都支持下拉关闭；新建食谱下拉仍会弹「还没保存」确认，避免误丢内容。

## 稳定性与构建

- 社区信息流改为 `ListView.builder` 懒加载；所有远程图片、猫图、头像和资源图按显示尺寸解码；全局图片缓存上限 48MB。
- 监听 Android `onTrimMemory` 与 Flutter 内存压力回调，低内存时清理解码图；退到后台时清理图片缓存。
- 连续选多张食谱图时串行压缩，封面/步骤图选择尺寸分别降到 1800 / 2000，降低解码峰值。
- 开发机 Gradle 配置从 8G 堆 / 4G Metaspace 降为 3G / 768M，关闭 daemon、并行与 VFS 监听，workers 限制为 2；清理构建与最终通用包构建实测 Java 峰值约 2.1–2.35GB、整机已用峰值约 9.7GB、最低剩余约 6.4GB。
- 电脑近期重启在 Windows 日志中表现为 Kernel-Power 41 + WHEA 硬件/固件错误（BugcheckCode=0，无蓝屏转储），属于供电/硬件/固件层问题；构建内存压缩只能降低触发概率。建议更新 BIOS/EC、检查原装电源与散热，低负载仍重启时送修。

## 构建命令

```bash
cd X:\flutter
KEY=$(cat X:\密钥\glm.key)
flutter build apk --release --dart-define=GLM_API_KEY="$KEY"
```

> 构建前关闭 Android 模拟器，构建结束后不要保留 Gradle daemon（本工程已在 `android/gradle.properties` 关闭）。
